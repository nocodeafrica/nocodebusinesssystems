# Usage Examples
# ==============

## Import Utilities
import { 
  asyncHandler,           // Error handling wrapper
  formatSuccessResponse,  // Success response formatter
  withModuleAuth,         // Auth + module check
  validateBody,           // Request body validation
  NotFoundError           // Typed error classes
} from '@/lib/api'

## Example API Route
export const GET = asyncHandler(async (request: NextRequest) => {
  // Authenticate user & check inventory module access
  const { supabase, auth } = await withModuleAuth(request, 'inventory')
  
  // Query data (RLS automatically enforced)
  const { data } = await supabase
    .from('products')
    .select('*')
    .eq('organization_id', auth.organizationId)
  
  // Return standardized response
  return formatSuccessResponse(data)
})

## Example Client Usage
import { listProducts } from '@/lib/api/example-usage'

const { data, meta } = await listProducts({
  page: 1,
  limit: 20,
  search: 'laptop',
  lowStock: true
})

# Authentication Flow
# ===================

1. User authenticates via Supabase Auth
   ↓
2. Receives JWT access token
   ↓
3. Includes token in API requests: Authorization: Bearer <token>
   ↓
4. API validates token and extracts user_id
   ↓
5. Queries organization_members to get organization_id
   ↓
6. Checks organization_subscriptions for module access
   ↓
7. Enforces RLS via organization_id filter
   ↓
8. Returns data only from user's organization


# Security Layers
# ===============

Layer 1: Authentication
└─ JWT token validation via Supabase Auth

Layer 2: Organization Context
└─ User must belong to an organization

Layer 3: Module Subscription
└─ Organization must have 'inventory' module enabled

Layer 4: Role-Based Access
└─ User role must have permission for the operation

Layer 5: Row-Level Security (RLS)
└─ Database enforces organization_id filtering

Layer 6: Input Validation
└─ Zod schemas validate all inputs

Layer 7: Business Logic Validation
└─ Prevent invalid operations (negative stock, duplicate SKUs)
